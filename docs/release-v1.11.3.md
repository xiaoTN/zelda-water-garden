# v1.11.3 — 修复慢帧误报 3D 不可用

## 原因与复现

旧逻辑以 requestAnimationFrame 回调间隔判断性能：连续两组慢窗口后降低画质，再两组慢窗口后永久停用渲染。自然场景 blocked 状态与初始化失败共用了“请启用硬件加速”提示。即使 WebGL context 正常，宿主调度慢也能触发同样的黑屏；后续 resize 清空画布且无法再绘制。

用真实页面、真实 WebGL 和受控 RAF 时间戳复现：每帧间隔 60 ms，运行 400 帧。修改前雪地 renderer/quality 均变为 unavailable，但 isContextLost() 为 false，并显示用户报告的原文。回归断言先失败，修改后雪地、云层、水面均保持 low + webgl；调整窗口后仍可绘制，水面物理步继续推进。该测试模拟回调调度，不代表设备实测 FPS。

当前用户预览的旧页面没有捕获到 WebGL 错误日志；无法从截图单独确定当时每一帧的状态。刷新修复后的同一浏览器后雪地和云层均正常渲染，因此没有证据要求用户开启硬件加速。

## 修改

- 保留持续慢帧自动降低像素数、几何数量和动画频率；回调慢不再永久停用有效的 WebGL renderer。
- 场景切换、窗口调整和页面重新可见时重置采样窗口，避免把过渡期的历史慢帧继续累计。
- 删除自然场景人为 blocked 状态。真正初始化失败与上下文丢失分别显示准确提示；水面错误状态使用调用点给出的原因。
- 将旧的“慢帧必须停用”浏览器断言替换为独立的三场景确定性回归脚本，并纳入 npm run test:browser。

## 验证

- npm run build：45 项单元测试、17 个离线文件包检查、源码审计、ZIP 内容和产物审计通过。
- npm run test:browser：慢帧回归、水面、自然场景与边缘交互完整套件通过（详见同版 evidence 报告）。
- 当前内置浏览器实际刷新、切换雪地与云层、划动验证正常，留在雪地预览。
- 未做 Android/iOS 真机性能验收。
